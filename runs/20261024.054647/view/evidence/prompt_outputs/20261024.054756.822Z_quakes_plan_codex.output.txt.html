# ARCHITECTURE: Quakes Application

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Defines the Python command-line application structure and module boundaries. |
| Depends On  | |
| Provides    | cli.main |

## Questions

- None.

## Purpose

The application is a Python 3.11+ command-line executable named `quakes`. It reads saved USGS GeoJSON for reports and uses the USGS FDSN event service for fetches. The application does not read the grader or embed report answers.

## Technology Stack

| Technology | Application |
|---|---|
| Python | Application code, tests, and command entry point; standard library only. |
| CLI | Root `quakes` executable and command parsing. |
| pytest | Automated project test suite. |
| USGS GeoJSON | Feed responses and saved report inputs. |
| Shell | POSIX test runner and supplied grader. |

## Modules and boundaries

- `cli.main(argv: list[str] | None = None) -> int` is the in-process entry point. The root executable delegates to it and uses its return value as the process exit status.
- `cli.testing.cli_runner(*args: str) -> tuple[int, str, str]` invokes `cli.main` without spawning a process.
- CLI parsing and help belong to `FEATURE-CLI.md`.
- GeoJSON reading, event normalization, and magnitude filtering belong to `FEATURE-EVENT-DATA.md`.
- Network access and fetch-file writing belong to `FEATURE-FETCH.md`.
- Each report calculation and CSV formatting belongs to its report feature.
- Diagnostics go to standard error. A failing command writes no standard output.

## Module ownership

| Boundary | Owner | Allowed access |
|---|---|---|
| Configuration | Command and feature modules | Command arguments only; no external configuration is required by the source contract. |
| File reads | Event data module | Read the supplied saved GeoJSON file. |
| File writes | Fetch module | Write a successful, validated response to the requested output file. |
| External service | Fetch module | Standard-library `urllib.request` for the USGS FDSN event service. |
| Persistence | None | The application has no database or other persistent store. |

# FEATURE: Command Line Interface

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Defines the quakes commands, their options, help, and argument validation. |
| Depends On  | ARCHITECTURE.md |
| Provides    | quakes fetch, quakes summary, quakes top, quakes daily, quakes regions, quakes near |
| Consumes    | cli.main |

## Questions

- None.

## Purpose

Users invoke `./quakes <command>`. The command name follows the executable, options may follow in any order, and report input files are positional. An option not listed for a command, a missing value, or an extra file is a usage error.

## Command interface

```text
quakes fetch --start <YYYY-MM-DD> --end <YYYY-MM-DD> [--min-mag <m>] --out <file>
quakes summary [--min-mag <m>] <file>
quakes top [--min-mag <m>] [--n <count>] <file>
quakes daily [--min-mag <m>] <file>
quakes regions [--min-mag <m>] <file>
quakes near --lat <deg> --lon <deg> --radius <km> [--min-mag <m>] <file>
```

- Decimal values match `-?[0-9]+(\.[0-9]+)?`.
- `--min-mag` defaults to `2.5` for fetch and applies to every report.
- `--n` is a positive integer and defaults to `10`.
- `near` requires all of `--lat`, `--lon`, and `--radius`; latitude is within −90 to 90, longitude within −180 to 180, and radius is positive.
- Each command and sub-verb provides help describing its usage.
- Malformed arguments, unknown commands, unsupported options, and missing or extra files return exit code `2`.

## Operational behavior

Usage diagnostics are written to standard error. A usage failure writes nothing to standard output. Operational failures use exit code `1`; success, including an empty report, uses exit code `0`.

# FEATURE: Earthquake Event Data

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Defines saved GeoJSON loading, event normalization, validation, and magnitude filtering. |
| Depends On  | ARCHITECTURE.md, FEATURE-CLI.md |
| Provides    | event loading, event normalization, magnitude filtering |
| Consumes    | cli.main |

## Questions

- None.

## Purpose

Report commands share one event-loading and filtering contract. Each GeoJSON feature is one event. The loader uses the feature `id`, `properties.mag`, `properties.place`, `properties.time`, `properties.tsunami`, and `geometry.coordinates` (`[longitude, latitude, depth_km]`), ignoring other fields.

## Event semantics

- A null magnitude excludes the event from every report.
- `--min-mag` retains events whose magnitude is at least the threshold.
- Times are UTC `YYYY-MM-DDTHH:MM:SSZ`, truncated to whole seconds. The event date is the first ten characters.
- The region is the text after the last `, ` in `place`, or all of `place` if there is no such separator. A null place normalizes to `Unknown`, also its region.
- Invalid JSON, unreadable files, and documents that are not objects with `"type": "FeatureCollection"` and a `features` array are operational failures: exit `1`, diagnostic on standard error, and no standard output.

## Shared interface

Provide `read_events(path)` to load normalized event records and `filter_events(events, min_mag)` to apply the threshold. A normalized record exposes `id`, `mag`, `place`, `time`, `date`, `tsunami`, `longitude`, `latitude`, `depth_km`, and `region`. Reports and fetch count handling use these shared semantics.

## Programmatic Acceptance

# FEATURE: Fetch USGS Feed

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Defines fetching, validating, and saving a USGS GeoJSON response. |
| Depends On  | ARCHITECTURE.md, FEATURE-CLI.md |
| Provides    | quakes fetch |
| Consumes    | cli.main |

## Questions

- None.

## Purpose

`quakes fetch` requests a date range from the USGS FDSN event service as GeoJSON and saves the response body unchanged after validating it as a GeoJSON FeatureCollection.

## Request and response

Use `urllib.request` with this query shape:

```text
https://earthquake.usgs.gov/fdsnws/event/1/query?format=geojson&starttime=<start>&endtime=<end>&minmagnitude=<m>&orderby=time-asc
```

`--min-mag` defaults to `2.5`. A successful response has HTTP status `200` and a FeatureCollection `features` array. Write the original response bytes unchanged to `--out` and report `fetched,<feature-count>` on standard output. Network errors, non-200 HTTP status, or invalid response content are operational failures: exit `1`, diagnostic on standard error, and no output file is written.

## Programmatic Acceptance

=== AC fetch-round-trip ===
Intent: Fetch writes the valid stub response bytes unchanged and creates the requested file.

import json
from pathlib import Path
from unittest.mock import patch
from cli.testing import cli_runner

body = json.dumps({
    "type": "FeatureCollection",
    "features": [],
}, separators=(",", ":")).encode("utf-8")
out = Path("acceptance-fetch.geojson")

        "status": 200,
        "read": lambda self: body,
        "__enter__": lambda self: self,

# FEATURE: Summary Report

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Defines the summary report over filtered earthquake events. |
| Depends On  | ARCHITECTURE.md, FEATURE-CLI.md, FEATURE-EVENT-DATA.md |
| Provides    | quakes summary |
| Consumes    | event loading, magnitude filtering |

## Questions

- None.

## Purpose

`quakes summary [--min-mag <m>] <file>` emits a CSV summary with event count, first and last UTC event times, minimum and maximum magnitude, mean magnitude rounded half up to two decimal places, and tsunami count.

## Report contract

The header is `events,first,last,min_mag,max_mag,mean_mag,tsunami`. Events are ordered by time for determining `first` and `last`. Magnitudes use one decimal place. With no matching events, the data row is `0,,,,,,0`. Output is CSV with newline line endings.

Provide `summarize(events)` as a calculation function returning the summary fields, and `format_summary(summary)` as the CSV formatter used by the CLI.

## Programmatic Acceptance
