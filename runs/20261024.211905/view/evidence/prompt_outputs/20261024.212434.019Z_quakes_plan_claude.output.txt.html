# FEATURE: Event Normalise

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Normalise event time, date and region and provide the shared number-formatting helpers. |
| Depends On  | FEATURE-FeedReader.md, ARCHITECTURE.md |
| Provides    | format_time, region_of, format_mag, format_one_decimal, format_two_decimal |
| Consumes    | read_events(path) |

## Questions

- None.

## Purpose

Turn the raw values the reader returns into the text every report writes. These are pure functions
in modules under the `cli` package, so each is unit-tested on its own.

## Interface

| Function | Input | Output |
|---|---|---|
| `format_time(ms)` | integer milliseconds since the Unix epoch | UTC `YYYY-MM-DDTHH:MM:SSZ`, truncated (not rounded) to whole seconds |
| `region_of(place)` | place text or `None` | text after the last `, ` in `place`, the whole `place` when it has none, `Unknown` for `None` |
| `format_mag(mag)` | number | one decimal place, so `5` becomes `5.0` |
| `format_one_decimal(value)` | number | one decimal place, rounded half up (depth and distance) |
| `format_two_decimal(value)` | number | two decimal places, rounded half up (mean magnitude) |

An event's date is the first 10 characters of its formatted time. Half-up rounding uses `decimal`
over `Decimal(str(value))`, never float formatting.

# FEATURE: Min Magnitude Filter

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Keep only events with magnitude at least the --min-mag value, for every report. |
| Depends On  | FEATURE-EventNormalise.md, FEATURE-CliDispatch.md |
| Provides    | filter_min_mag(events, m), --min-mag option |
| Consumes    | read_events(path) |

## Questions

- None.

## Purpose

`filter_min_mag(events, m)` is a pure function over the event list the reader returns. It keeps
events with `mag >= m`, preserving order. It sits in the common pipeline (read, filter, compute,
format) shared by every report command, so `--min-mag` means the same thing in all of them. When
`--min-mag` is absent no filtering beyond the reader's null-magnitude exclusion happens. A
`--min-mag` value that does not match `-?[0-9]+(\.[0-9]+)?` is a usage error (exit 2).

## Programmatic Acceptance

# FEATURE: Summary

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | The summary report: event count, time span, magnitude range, mean and tsunami count. |
| Depends On  | FEATURE-MinMagFilter.md, FEATURE-ExitCodes.md |
| Provides    | quakes summary |
| Consumes    | filter_min_mag(events, m), format_time |

## Questions

- None.

## Purpose

`quakes summary [--min-mag <m>] <file>` writes the header `events,first,last,min_mag,max_mag,mean_mag,tsunami`
and one row. `first` and `last` are the earliest and latest event times, `min_mag` and `max_mag` have
one decimal, `mean_mag` has two decimals rounded half up, and `tsunami` counts events whose `tsunami`
equals `1`. With no events the row is `0,,,,,,0`. Output is written with the `csv` module and `\n`
line endings; the report is computed fully before anything is written.

## Programmatic Acceptance

=== AC summary-values ===
Intent: The summary row carries the count, earliest and latest time, magnitude range, half-up mean and tsunami count computed from the file.

import csv
import io

from cli.testing import cli_runner


def iso(ms):
    return datetime.fromtimestamp(ms // 1000, timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")


mags = [5.0, 5.1, 5.1]
times = [1735800000999, 1735700000000, 1735900000500]
tsunamis = [1, 0, 1]

    for i in range(len(mags))
]

print(err)

expected = [
    str(len(mags)),
    iso(min(times)),
    iso(max(times)),
    f"{min(mags):.1f}",
    f"{max(mags):.1f}",
    str(mean),
    str(sum(1 for t in tsunamis if t == 1)),
]
assert rows[1] == expected
assert "\r" not in out

# FEATURE: Top

| Field       | Value |
|-------------|-------|

## Purpose

`quakes top [--min-mag <m>] [--n <count>] <file>` writes the header `time,mag,depth_km,place,id` and the

# FEATURE: Daily

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | The per-day report: events and maximum magnitude per UTC date, with a TOTAL row. |
| Depends On  | FEATURE-MinMagFilter.md, FEATURE-ExitCodes.md |
| Provides    | quakes daily |
| Consumes    | filter_min_mag(events, m), format_time |

## Questions

- None.

## Purpose

`quakes daily [--min-mag <m>] <file>` writes the header `date,events,max_mag`, one row per UTC date
that has events in ascending order, then `TOTAL,<events>,<max_mag>` covering all events. The date is
the first 10 characters of the event time. Magnitudes have one decimal. With no events the only row
after the header is `TOTAL,0,` with an empty maximum.

## Programmatic Acceptance
