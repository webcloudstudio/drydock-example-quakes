# FEATURE: Regions

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | The regions report counts events and the maximum magnitude per region of a saved feed. |
| Depends On  | FEATURE-MinMagFilter.md, FEATURE-ExitCodes.md |
| Provides    | quakes regions |
| Consumes    | filter_min_mag(events, m), region_of |

## Questions

- None.

## Purpose

`quakes regions [--min-mag <m>] <file>` answers which regions are most active. It reads the file,
applies the magnitude filter, groups events by region, and writes one CSV row per region.

## Trigger

The command line `quakes regions [--min-mag <m>] <file>`.

## Sequence

1. Read the file and drop events with a null magnitude (reader).
2. Keep events with `mag >= m` when `--min-mag` is given (filter).
3. Compute one row per region: event count and maximum magnitude (compute).
4. Format and write CSV with the `csv` module, `\n` line endings, UTF-8 (formatter).

## Output

Header `region,events,max_mag`. Rows are ordered by `events` descending, then `region` ascending.
Region text is compared by byte value (its UTF-8 encoding). `max_mag` is written with one decimal
place. The region of an event is the text after the last `, ` in its place, or the whole place when
there is none; a null place is `Unknown`, which is its own region. With no matching events only the
header is written and the exit status is 0.

## Reads

The saved GeoJSON file named on the command line. Nothing else.

## Writes

CSV on standard output only.

# FEATURE: Near

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | The near report lists events within a haversine distance of a point, nearest first. |
| Depends On  | FEATURE-MinMagFilter.md, FEATURE-ExitCodes.md |
| Provides    | quakes near, haversine_km |
| Consumes    | filter_min_mag(events, m), format_time |

## Questions

- None.

## Purpose

`quakes near --lat <deg> --lon <deg> --radius <km> [--min-mag <m>] <file>` lists the events whose
great-circle distance from the given point is at most the radius.

## Trigger

The command line `quakes near ...` with all of `--lat`, `--lon` and `--radius`.

## Sequence

1. Read the file and drop events with a null magnitude.
2. Apply `--min-mag` when given.
3. Compute each event's haversine distance from (`--lat`, `--lon`) with `haversine_km`.
4. Keep events whose unrounded distance is `<= --radius` (decision Q-003).
5. Order by unrounded distance ascending, then time ascending.
6. Write CSV; distance is rounded half up to one decimal place.

## Distance

Haversine on a sphere of radius 6371.0 km, angles in radians:

```text
h = sin^2((lat2 - lat1) / 2) + cos(lat1) * cos(lat2) * sin^2((lon2 - lon1) / 2)
d = 2 * 6371.0 * asin(sqrt(h))
```

`haversine_km(lat1, lon1, lat2, lon2) -> float` is a pure function in the compute module.

## Output

Header `distance_km,time,mag,place,id`. Time is UTC `YYYY-MM-DDTHH:MM:SSZ`; magnitude has one decimal
place. Places containing commas are quoted by the `csv` module. With no matching events only the
header is written and the exit status is 0.

## Reads

The saved GeoJSON file named on the command line.

## Writes

CSV on standard output only.

# FEATURE: Fetch

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | The fetch command downloads a period of the USGS event feed as GeoJSON and saves the body unchanged. |
| Depends On  | FEATURE-CliDispatch.md, FEATURE-ExitCodes.md, FEATURE-FeedReader.md |
| Provides    | quakes fetch, http_get |
| Consumes    | quakes <command> dispatch |

## Questions

- None.

## Purpose

`quakes fetch --start <YYYY-MM-DD> --end <YYYY-MM-DD> [--min-mag <m>] --out <file>` saves a period
of the USGS FDSN event feed so that report commands can read it later.

## Request

GET `https://earthquake.usgs.gov/fdsnws/event/1/query` with the query parameters `format=geojson`,
`starttime=<start>`, `endtime=<end>`, `minmagnitude=<m>` (default `2.5`) and `orderby=time-asc`.

## HTTP seam

All network access goes through one replaceable function, `http_get(url)`, which returns the status
code and the body bytes. It calls `urllib.request.urlopen` through the module attribute
(`urllib.request.urlopen(...)`, never `from urllib.request import urlopen`), so a test can replace
the HTTP call with a stub. An `HTTPError` is returned as its status code. No test uses the network.

## Sequence

1. Parse and validate options (`--start`, `--end`, `--out` required; `--min-mag` optional).
2. Request the URL through `http_get`.
3. On status 200, parse the body as a GeoJSON FeatureCollection (failure handling is in
   FEATURE-FetchErrors.md).
4. Write the body bytes unchanged to `--out`.
5. Write `fetched,<count>` to standard output, where `<count>` is the number of features.

Missing `--start`, `--end` or `--out`, an extra positional argument, or a malformed `--min-mag` is a
usage error (exit 2).

## Reads

The USGS event service.

## Writes

The file named by `--out`; `fetched,<count>` on standard output.

## Programmatic Acceptance

# FEATURE: Fetch Errors

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | The fetch command fails with exit 1 and writes no file on network, HTTP or body errors. |
| Depends On  | FEATURE-Fetch.md |
| Provides    | fetch failure behavior |
| Consumes    | http_get |

## Questions

- None.

## Purpose

Make `quakes fetch` safe: it never leaves a file behind that report commands could mistake for a
valid feed.

## Failure cases

Each of these is an operational failure: exit 1, nothing on standard output, one diagnostic line on
standard error, and no file written at `--out`.

- A network error (for example `URLError`, a timeout, or `OSError`).
- An HTTP status other than 200.
- A body that is not valid JSON (including bytes that are not UTF-8).
- A JSON body that is not an object with `"type": "FeatureCollection"` and a `features` array.

The body is validated completely before the output path is opened.

## Reads

The USGS event service through `http_get`.

## Writes

Nothing on failure.
