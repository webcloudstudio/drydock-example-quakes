# ARCHITECTURE: Quakes

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Module layout, boundaries and technical decisions for the `quakes` earthquake feed reporter command-line tool. |
| Depends On  | None |
| Provides    | quakes executable, cli.main, cli.testing.cli_runner, cli.errors.UsageError, cli.errors.OperationalFailure |
| Consumes    | None |

## Questions

- None.

## Purpose

`quakes` is a Python 3.11+ standard-library command-line tool. `quakes fetch` saves a period of the
USGS FDSN event feed as a GeoJSON file. Five report commands (`summary`, `top`, `daily`, `regions`,
`near`) read a saved file and write a CSV report to standard output. Every report value is computed
from the file being read; nothing is embedded.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`, which remains the decision of record.

| Technology | Where it applies |
|---|---|
| Python 3.11+ (standard library only) | All application code: `cli/` package and the `quakes` executable. |
| CLI (`cli.md`) | The `quakes` entry point and the `cli` package with `main(argv) -> int`. |
| pytest | The project test suite under `tests/`, run through `bin/test.sh`. |
| USGS GeoJSON | Input format for every report; fetched with `urllib.request`. |
| POSIX sh | `bin/test.sh` and the supplied grader `sources/run.sh`. |

## Module Layout

All application code lives in the `cli` package at the application root.

| Module | Responsibility | Built by story |
|---|---|---|
| `quakes` (root, executable) | `#!` Python launcher that calls `cli.main` and exits with its return value | foundation |
| `cli/__init__.py` | `main(argv) -> int`: help check, parse, dispatch, exit-code mapping, writing stdout | foundation, then feature stories |
| `cli/testing.py` | `cli_runner(*args) -> (exit_code, stdout, stderr)` | foundation |
| `cli/errors.py` | `UsageError` and `OperationalFailure`, both `Exception` subclasses | foundation |
| `cli/options.py` | `COMMANDS`, `Invocation`, `parse_args(argv)` | feature-cli-dispatch |
| `cli/commands.py` | `HANDLERS` registry and `dispatch(invocation) -> str` | feature-cli-dispatch |
| `cli/help.py` | `wants_help(argv)`, `help_text(command)` | feature-help |
| `cli/reader.py` | `Event`, `read_events(path)` | feature-feed-reader |
| `cli/normalise.py` | `format_time`, `region_of`, number formatting helpers | feature-event-normalise |
| `cli/filtering.py` | `filter_min_mag(events, m)` | feature-min-mag |
| `cli/reports.py` and per-report modules | One compute function and one format function per report | report stories |
| `cli/fetch.py` | `http_get(url)` and the fetch handler | feature-fetch |

Reading the file, filtering, computing each report, and formatting are separate functions, each
unit-tested on its own.

## Control Flow

`main(argv)` runs, in order:

1. Reconfigure standard output to UTF-8 with `\n` newlines when the stream supports it.
2. If `cli.help.wants_help(argv)`, write the help text to standard output and return `0`.
3. `invocation = parse_args(argv)`, then `text = commands.dispatch(invocation)`.
4. Write `text` to standard output once, only after the handler has returned, and return `0`.
5. `UsageError` returns `2` and `OperationalFailure` returns `1`. Each writes exactly one diagnostic
   line to standard error and nothing to standard output.

A handler is a function `handler(invocation) -> str` returning the complete standard-output text. A
handler never writes to standard output itself. This is what guarantees that a failing command
writes nothing to standard output.

## Boundaries and Ownership

| Boundary | Owning module | Notes |
|---|---|---|
| Local file reads | `cli/reader.py` | The only module that opens a feed file for reading. |
| Network | `cli/fetch.py` `http_get` | The only module that opens a connection; tests replace `http_get`. |
| Standard output | `cli/__init__.py` `main` | Handlers return text. |
| Standard error | `cli/__init__.py` `main` | Diagnostics only; never compared. |
| Persistence, configuration, external stores | None | The product has no database or configuration. |

## Technical Decisions

- Exit codes: `0` success (including a report with no matching events), `1` operational failure,
  `2` usage error.
- Magnitudes are held as `decimal.Decimal` built from `str(value)` so that half-up rounding is exact.
- CSV is written with Python's `csv` module, `lineterminator="\n"`, and encoded as UTF-8.
- Application code never reads `sources/run.sh` or the snapshot and never embeds a report row,
  count, or distance.

# FEATURE: Cli Dispatch

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Parse the command and its options in any order with the file last, and dispatch to the registered command handler. |
| Depends On  | ARCHITECTURE.md |
| Provides    | quakes <command> dispatch, cli.options.parse_args, cli.options.COMMANDS, cli.options.Invocation, cli.commands.HANDLERS, cli.commands.dispatch |
| Consumes    | cli.main, cli.errors.UsageError, cli.errors.OperationalFailure |

## Questions

- None.

## Purpose

`quakes <command> [options] [<file>]`. The command comes first, options follow in any order, and
the file is last. Any malformed command line is a usage error. This feature parses and validates the
shape of the command line and routes a parsed invocation to a handler; reports, validation of `near`
ranges, and exit-code mapping belong to other features.

## Trigger

Every invocation of `quakes`.

## Interface

- `cli.options.COMMANDS`: tuple `("fetch", "summary", "top", "daily", "regions", "near")`.
- `cli.options.Invocation`: frozen dataclass with `command: str`, `options: dict[str, str]`, and
  `file: str | None`. `options` is keyed by the option name without its leading `--` (`min-mag`,
  `n`, `lat`, `lon`, `radius`, `start`, `end`, `out`) and holds the value text exactly as given.
  An option that was not given is absent from the dict; the owning command applies defaults
  (`n` = 10, fetch `min-mag` = 2.5).
- `cli.options.parse_args(argv: list[str]) -> Invocation`, raising `cli.errors.UsageError`.
- `cli.commands.HANDLERS`: plain `dict[str, Callable[[Invocation], str]]`; each handler returns the
  complete standard-output text.
- `cli.commands.dispatch(invocation) -> str`: calls `HANDLERS[invocation.command]`; when no handler is
  registered it raises `cli.errors.OperationalFailure`.

## Rules

1. `argv[0]` is the command; an unknown command or an empty `argv` is a usage error.
2. The token after an option name is always that option's value, even when it begins with `-`
   (so `--lat -5.25` is valid). A missing value is a usage error.
3. Options accepted per command:

   | Command | Options | Positional file |
   |---|---|---|
   | `fetch` | `--start`, `--end`, `--out` (all required), `--min-mag` | none (an extra positional is a usage error) |
   | `summary`, `daily`, `regions` | `--min-mag` | exactly one, last |
   | `top` | `--min-mag`, `--n` | exactly one, last |
   | `near` | `--lat`, `--lon`, `--radius`, `--min-mag` | exactly one, last |

4. Any other option, or an option the command does not list, is a usage error.
5. An option given more than once is a usage error.
6. `--min-mag`, `--lat`, `--lon` and `--radius` values must match `-?[0-9]+(\.[0-9]+)?`. `--n` must be
   a positive integer (`0`, negatives, decimals and text are usage errors). `--start` and `--end`
   must have the shape `YYYY-MM-DD`.
7. A report command with no file, or with more than one file, is a usage error.
8. For `near`, the presence of `--lat`, `--lon`, `--radius` and the range checks belong to
   FEATURE-NearValidation.md; the parser only accepts them.

# FEATURE: Exit Codes

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Map outcomes to exit codes 0, 1 and 2 and guarantee empty standard output with one standard-error line on failure. |
| Depends On  | ARCHITECTURE.md, FEATURE-CliDispatch.md |
| Provides    | exit code contract |
| Consumes    | quakes <command> dispatch, cli.errors.UsageError, cli.errors.OperationalFailure, cli.commands.dispatch |

## Questions

- None.

## Purpose

`cli.main` turns the result of parsing and dispatching into a process exit code and guarantees that a
failing command writes nothing to standard output.

## Rules

| Code | Meaning |
|---|---|
| `0` | Success, including a report with no matching events. The handler text is written to standard output exactly once. |
| `1` | Operational failure (`OperationalFailure`): file unreadable or not a FeatureCollection; fetch network or HTTP failure. |
| `2` | Usage error (`UsageError`): any malformed command line. |

- `main` writes the handler's text to standard output only after the handler returned, so a failing
  command has written nothing to standard output.
- A failure writes exactly one diagnostic line to standard error (the exception message on a single
  line, no traceback). Standard error is never compared.
- `main` configures standard output as UTF-8 with `\n` newlines when the stream supports
  `reconfigure`, and writes the text without adding or altering line endings.

# FEATURE: Help

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Provide help text for the program and for each command, shown by `--help`. |
| Depends On  | ARCHITECTURE.md, FEATURE-CliDispatch.md |
| Provides    | --help for quakes and each command, cli.help.wants_help, cli.help.help_text |
| Consumes    | quakes <command> dispatch, cli.options.COMMANDS |

## Questions

- None.

## Purpose

Every command has help text so a user can discover its options. Help is requested output, not a
failure: it is written to standard output and exits `0` (decision Q-001).

## Interface

- `cli.help.help_text(command: str | None) -> str`: program-level help when `command` is `None`
  (listing every command), otherwise that command's synopsis and options. Each command's text is
  distinct.
- `cli.help.wants_help(argv: list[str]) -> bool`: `True` when `argv[0]` is `--help`, or when
  `argv[0]` is a known command and `--help` appears later in `argv`; otherwise `False`.

## Rules

1. `quakes --help` writes the program help and exits `0`.
2. `quakes <command> --help` for each of `fetch`, `summary`, `top`, `daily`, `regions`, `near` writes
   that command's help and exits `0`.
3. Help is written before any file is read or any other validation is attempted.
4. `quakes frobnicate --help` is not help: the unknown command is a usage error (exit `2`).
5. `main` checks `wants_help` first, as step 2 of the control flow in ARCHITECTURE.md.

## Programmatic Acceptance

# FEATURE: Feed Reader

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Read a saved USGS GeoJSON FeatureCollection file into a list of events. |
| Depends On  | ARCHITECTURE.md |
| Provides    | read_events(path), cli.reader.Event |
| Consumes    | cli.errors.OperationalFailure |

## Questions

- None.

## Purpose

`read_events` is the only function that reads a feed file. It turns the file into events, ignores
every field it does not need, and excludes events with no magnitude. Normalisation (time, region),
filtering and formatting are other functions.

## Interface

`cli.reader.Event` is a frozen dataclass:

| Field | Type | Source |
|---|---|---|
| `id` | `str` | feature `id` |
| `mag` | `decimal.Decimal` | `Decimal(str(properties.mag))` |
| `place` | `str \| None` | `properties.place`, unchanged (`None` stays `None`) |
| `time_ms` | `int` | `properties.time`, milliseconds since the Unix epoch |
| `tsunami` | `int` | `properties.tsunami` (`1` or `0`) |
| `lon` | `float` | `geometry.coordinates[0]` |
| `lat` | `float` | `geometry.coordinates[1]` |
| `depth_km` | `float` | `geometry.coordinates[2]` |

`cli.reader.read_events(path: str | os.PathLike) -> list[Event]` returns events in file order.

## Rules

1. The file is read as UTF-8. A file that cannot be read, is not valid UTF-8, or is not JSON raises
   `cli.errors.OperationalFailure`.
2. The top level must be an object with `"type": "FeatureCollection"` and a `features` array;
   otherwise `OperationalFailure`.
3. Every other field of a feature is ignored.
4. A feature whose `properties.mag` is `null` is excluded.
5. A feature that lacks a field the reader needs (other than a null `mag`, and a null `place` which is
   kept as `None`) raises `OperationalFailure` rather than being skipped (decision Q-004).
6. An empty `features` array yields an empty list.

## Programmatic Acceptance

=== AC reader-fields ===
Intent: read_events returns one Event per feature with the mapped fields, in file order, excluding null-magnitude features.
Requires: executable=python3; scope=test

import json
import os
import sys
import tempfile
from decimal import Decimal

sys.path.insert(0, os.getcwd())

from cli.reader import Event, read_events

def feature(fid, mag, place, ms, tsunami, lon, lat, depth):
    return {
        "type": "Feature",
        "properties": {"mag": mag, "place": place, "time": ms, "tsunami": tsunami,
                       "updated": 1, "status": "reviewed", "sig": 400},
        "geometry": {"type": "Point", "coordinates": [lon, lat, depth]},
        "id": fid,
    }

features = [
    feature("ev-a", 5.1, "12 km N of Alpha, Beta", 1735706358208, 0, 169.3819, -20.9273, 22),
    feature("ev-null", None, "ignored", 1735706358209, 0, 1.0, 2.0, 3),
    feature("ev-b", 7, None, 1736211916734, 1, 87.3781, 28.6036, 10.5),
]
doc = {"type": "FeatureCollection", "metadata": {"count": 3}, "features": features}
with tempfile.TemporaryDirectory() as tmp:
    path = os.path.join(tmp, "feed.geojson")
    with open(path, "w", encoding="utf-8") as handle:
        json.dump(doc, handle)
    events = read_events(path)

expected = [f for f in features if f["properties"]["mag"] is not None]
assert len(events) == len(expected)
for event, src in zip(events, expected):
    assert isinstance(event, Event)
    props = src["properties"]
    lon, lat, depth = src["geometry"]["coordinates"]
    assert event.id == src["id"]
    assert event.mag == Decimal(str(props["mag"]))
    assert event.place == props["place"]
    assert event.time_ms == props["time"]
    assert event.tsunami == props["tsunami"]
    assert event.lon == lon
    assert event.lat == lat
    assert event.depth_km == depth
=== END AC reader-fields ===

=== AC reader-operational-failures ===
Intent: Unreadable, non-JSON, non-UTF-8, non-FeatureCollection, and malformed-feature files raise OperationalFailure.
Requires: executable=python3; scope=test

import json
import os
import sys
import tempfile

sys.path.insert(0, os.getcwd())

from cli.errors import OperationalFailure
from cli.reader import read_events

good_feature = {
    "type": "Feature",
    "properties": {"mag": 5.0, "place": "p", "time": 1000, "tsunami": 0},
    "geometry": {"type": "Point", "coordinates": [1.0, 2.0, 3.0]},
    "id": "ok",
}
no_geometry = {
    "type": "Feature",
    "properties": {"mag": 5.0, "place": "p", "time": 1000, "tsunami": 0},
    "id": "broken",
}
payloads = {
    "not-json": b"this is not json\n",
    "not-utf8": b"\xff\xfe\xfa\xfb",
    "single-feature": json.dumps({"type": "Feature", "properties": {}, "geometry": None}).encode("utf-8"),
    "no-features": json.dumps({"type": "FeatureCollection"}).encode("utf-8"),
    "features-not-list": json.dumps({"type": "FeatureCollection", "features": {}}).encode("utf-8"),
    "json-list": json.dumps([good_feature]).encode("utf-8"),
    "missing-geometry": json.dumps({"type": "FeatureCollection", "features": [good_feature, no_geometry]}).encode("utf-8"),
}
survivors = []
with tempfile.TemporaryDirectory() as tmp:
    for name, payload in payloads.items():
        path = os.path.join(tmp, name + ".json")
        with open(path, "wb") as handle:
            handle.write(payload)
        try:
            read_events(path)
        except OperationalFailure:
            continue
        survivors.append(name)
    try:
        read_events(os.path.join(tmp, "no-such-file.geojson"))
    except OperationalFailure:
        pass
    else:
        survivors.append("no-such-file")
print(survivors)
assert survivors == []
=== END AC reader-operational-failures ===

## Guardrails

- The reader never reads `sources/run.sh` or the snapshot and embeds no event data.
- Every field other than `id`, `mag`, `place`, `time`, `tsunami` and `geometry.coordinates` is ignored.
- A failure to read the file never produces partial events.
