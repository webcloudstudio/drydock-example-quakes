<requirement name="build-cli-tool" stories="foundation">
Build a command-line tool that downloads earthquake data from the United States Geological Survey
(USGS) and reports on it.
</requirement>
<requirement name="stack-python-stdlib" stories="foundation">
Implement in Python 3.11 or newer using only the standard library (`urllib.request` for HTTP).
Tests run under pytest. The product is an executable named `quakes` at the application root.
</requirement>
<requirement name="run-harness-scoring" stories="verification">
`sources/run.sh` is the scoring entry point. It is supplied, not authored, and is staged verbatim
into the application root with the snapshot. `drydock uat` runs `sh sources/run.sh` from the
completed application root and takes its exit code and output as the score.
</requirement>
<requirement name="command-line-grammar" stories="feature-cli-dispatch,feature-help">
The command comes first, options follow it in any order, and the file is last. An option that the
command does not list is a usage error. `<m>`, `<deg>`, and `<km>` are decimals matching
`-?[0-9]+(\.[0-9]+)?`. `<count>` is a positive integer, default `10`.
</requirement>
<requirement name="fetch-feed" stories="feature-fetch">
`fetch` requests
`https://earthquake.usgs.gov/fdsnws/event/1/query?format=geojson&starttime=<start>&endtime=<end>&minmagnitude=<m>&orderby=time-asc`
(`--min-mag` defaults to `2.5`) and writes the response body unchanged to `<file>`. It writes
`fetched,<count>` to standard output, where `<count>` is the number of features.
</requirement>
<requirement name="fetch-failure" stories="feature-fetch-errors">
A network error,
an HTTP status other than 200, or a body that is not a GeoJSON FeatureCollection is an operational
failure, and no file is written.
</requirement>
<requirement name="fetch-stub-tests" stories="feature-fetch-stub-tests">
Tests of `fetch` replace the HTTP call with a stub; they never use
the network.
</requirement>
<requirement name="read-feed-file" stories="feature-feed-reader">
The file is a GeoJSON `FeatureCollection` as the USGS feed returns it. A file that cannot be
read, is not JSON, or is not an object with `"type": "FeatureCollection"` and a `features`
array is an operational failure.
</requirement>
<requirement name="read-event-fields" stories="feature-feed-reader">
Each feature is one event. The tool reads `id`, `properties.mag`, `properties.place`,
`properties.time` (milliseconds since the Unix epoch), `properties.tsunami` (`1` or `0`), and
`geometry.coordinates` (`[longitude, latitude, depth_km]`). Every other field is ignored.
</requirement>
<requirement name="exclude-null-mag" stories="feature-feed-reader">
A feature whose `mag` is `null` is excluded from every report.
</requirement>
<requirement name="min-mag-filter" stories="feature-min-mag">
`--min-mag <m>` keeps only events with `mag >= m`. It applies to every report.
</requirement>
<requirement name="time-format" stories="feature-event-normalise">
**Time** is written in UTC as `YYYY-MM-DDTHH:MM:SSZ`, truncated to whole seconds. An event's
date is the first 10 characters.
</requirement>
<requirement name="region-rule" stories="feature-event-normalise">
**Region** is the text after the last `, ` (comma, space) in `place`, or the whole of `place`
when it has none. A `null` place is `Unknown`, which is also its region.
</requirement>
<requirement name="number-formatting" stories="feature-event-normalise">
- Magnitudes are written with one decimal place: `5.0`, `7.1`.
- `mean_mag` is written with two decimal places, rounded half up.
- `depth_km` and `distance_km` are written with one decimal place, rounded half up.
</requirement>
<requirement name="csv-output" stories="feature-event-normalise,feature-summary,feature-top,feature-daily,feature-regions,feature-near">
- Text is compared by byte value.
- Output is CSV on standard output with `\n` line endings, written with Python's `csv` module, so
  a place containing a comma is quoted. Place names contain non-ASCII characters and are written
  as UTF-8.
</requirement>
<requirement name="summary-report" stories="feature-summary">
| `summary` | `events,first,last,min_mag,max_mag,mean_mag,tsunami` | One row. `first` and `last` are the earliest and latest event times. `tsunami` counts events with `tsunami` equal to `1`. With no events: `0,,,,,,0`. |
</requirement>
<requirement name="top-report" stories="feature-top">
| `top` | `time,mag,depth_km,place,id` | The `--n` largest events, by `mag` descending, then time ascending. |
</requirement>
<requirement name="daily-report" stories="feature-daily">
| `daily` | `date,events,max_mag` | One row per date that has events, ascending, then `TOTAL,<events>,<max_mag>`. With no events, the max is empty: `TOTAL,0,`. |
</requirement>
<requirement name="regions-report" stories="feature-regions">
| `regions` | `region,events,max_mag` | One row per region, by events descending, then region ascending. |
</requirement>
<requirement name="near-report" stories="feature-near">
| `near` | `distance_km,time,mag,place,id` | Events whose distance from (`--lat`, `--lon`) is at most `--radius` km, by distance ascending, then time ascending. |
</requirement>
<requirement name="haversine-distance" stories="feature-near">
**Distance** is the haversine great-circle distance on a sphere of radius 6371.0 km:
</requirement>
<requirement name="failure-output" stories="feature-exit-codes">
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="exit-codes" stories="feature-exit-codes">
| `0` | Success, including a report with no matching events. |
| `1` | Operational failure: file unreadable or not a FeatureCollection; `fetch` network or HTTP failure. |
</requirement>
<requirement name="usage-error-exit" stories="feature-exit-codes,feature-cli-dispatch,feature-near-validation">
| `2` | Usage error: unknown command or option, an option the command does not take, missing or malformed value, `--lat` outside −90 to 90, `--lon` outside −180 to 180, `--radius` not positive, `near` without all three of `--lat`, `--lon`, and `--radius`, missing or extra file. |
</requirement>
<requirement name="test-script" stories="feature-test-runner">
The completed application provides a POSIX-compatible `bin/test.sh` that runs its own pytest suite
from the application root and exits zero only when every test passes.
</requirement>
<requirement name="test-coverage" stories="feature-test-runner,feature-fetch-stub-tests">
The suite covers each report,
each option, the region and distance rules, `fetch` against a stubbed HTTP response, and each exit
code, using files written by the tests.
</requirement>
