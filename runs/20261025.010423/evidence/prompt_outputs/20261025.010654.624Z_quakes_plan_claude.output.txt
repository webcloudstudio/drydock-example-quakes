# ARCHITECTURE: Quakes

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Module layout, boundaries, and technical decisions for the standard-library-only `quakes` command-line earthquake reporter. |
| Depends On  | None |
| Provides    | project tree, pytest runner |

## Questions

- None.

## Purpose

`quakes` is a single-process Python 3.11+ command-line tool at the application root. `fetch` downloads a USGS FDSN GeoJSON feed to a file. Five report commands (`summary`, `top`, `daily`, `regions`, `near`) read a saved file, filter it, compute rows, and print CSV to standard output.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file is the decision of record.

| Technology | Where it applies |
|---|---|
| Python 3.11+ (standard library only) | All application code. `urllib.request` for HTTP, `json`, `csv`, `decimal`, `datetime`, `math`, `re`. |
| CLI | The `quakes` executable and the `cli` package. |
| pytest | Test runner behind `bin/test.sh`; the only development dependency. |
| USGS GeoJSON | Input format. |
| POSIX sh | `bin/test.sh`. |

## Project Layout

| Path | Role |
|---|---|
| `quakes` | Executable launcher at the application root; calls `cli.main` and exits with its return value. |
| `pyproject.toml`, `uv.lock` | Dependency manifest and lockfile. Runtime dependencies: none. |
| `.venv` | Environment created by `uv venv`. |
| `conftest.py` | Exposes the `cli_runner` pytest fixture from `cli.testing`. |
| `cli/__init__.py` | `main(argv=None) -> int`, the command registry `COMMANDS`, exit-code mapping. |
| `cli/errors.py` | `UsageError` (exit 2) and `OperationalError` (exit 1). |
| `cli/options.py` | `parse_args(argv) -> Parsed`. |
| `cli/formatting.py` | `format_time`, `format_mag`, `format_mean`, `format_decimal`, `render_csv`, `write_csv`. |
| `cli/feed.py` | `read_feed(path)`, `extract_events(features)`, `Event`, `filter_events(events, min_mag)`. |
| `cli/reports.py` | One pure function per report, plus `haversine_km`. |
| `cli/fetch.py` | `build_url`, `http_get`, the fetch command. |
| `cli/testing.py` | `cli_runner(*args) -> (exit_code, stdout, stderr)`. |
| `tests/` | Application pytest suite. |
| `bin/test.sh` | POSIX sh wrapper that runs the pytest suite. |
| `sources/` | Read-only scoring assets; never modified and never read by application code. |

## Boundaries and Interfaces

Reading the file, filtering, computing each report, and formatting are separate functions:

1. `read_feed(path) -> list[dict]` validates and returns raw features.
2. `extract_events(features) -> list[Event]` normalizes and drops null-magnitude events.
3. `filter_events(events, min_mag) -> list[Event]` applies `--min-mag`.
4. A report function maps events (and its options) to a list of rows, each row a list of already-formatted strings.
5. `write_csv(rows, stream=None)` writes rows with the `csv` module.

`Parsed` (returned by `parse_args`) is a dataclass with fields `command: str`, `min_mag: float | None`, `n: int`, `lat: float | None`, `lon: float | None`, `radius: float | None`, `start: str | None`, `end: str | None`, `out: str | None`, `file: str | None`. `n` defaults to `10`. `min_mag` is `None` for report commands when omitted and `2.5` for `fetch` when omitted.

Command handlers are registered in `cli.COMMANDS: dict[str, Callable[[Parsed], str]]`. A handler returns the complete standard-output text for the command. `main` writes that text to standard output only after the handler returns, so a failing command leaves standard output empty.

## Exit Codes and Channels

| Code | Cause |
|---|---|
| 0 | Success, including a report with no matching events. |
| 1 | `OperationalError`: unreadable file, not a FeatureCollection, fetch network/HTTP/body failure. |
| 2 | `UsageError`: any malformed invocation. |

A failing command writes nothing to standard output and exactly one diagnostic line to standard error. Standard error is never compared by the grader.

## Technical Decisions

- Half-up rounding uses `decimal.Decimal(repr(x))` quantized with `ROUND_HALF_UP`; built-in `round()` is not used.
- Text ordering is by byte value (plain Python string comparison on code points, with UTF-8 output).
- Tests stub `cli.fetch.http_get`; no test opens a network connection.
- No report row, count, or distance is hardcoded; every value comes from the file read.

## Module Ownership

No persistent store, configuration file, or external service other than the USGS HTTP endpoint exists. File I/O is owned by `cli.feed` (reading) and `cli.fetch` (writing the fetched file). HTTP is owned by `cli.fetch.http_get`. No `DATABASE.md` applies.

# FEATURE: CLI Foundation

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Publishes the cli package, its main entry point, the cli_runner test helper, and the executable quakes launcher. |
| Depends On  | ARCHITECTURE.md |
| Provides    | cli.main, cli.testing.cli_runner, ./quakes |

## Questions

- None.

## Purpose

This foundation stands up the command-line entry point everything else registers into. It delivers the `cli` package, `main(argv=None) -> int`, the in-process `cli_runner` helper, and an executable file named `quakes` at the application root.

## Interface

- `cli.main(argv: list[str] | None = None) -> int` — when `argv` is `None` it uses `sys.argv[1:]`. Returns the process exit code and never raises for `UsageError` or `OperationalError`.
- `cli.COMMANDS` — registry mapping command name to a handler `Callable[[Parsed], str]` returning the full standard-output text.
- `cli.testing.cli_runner(*args) -> tuple[int, str, str]` — runs `main` in-process with redirected stdout and stderr and returns `(exit_code, stdout, stderr)`.
- `conftest.py` exposes `cli_runner` as a pytest fixture.
- `./quakes` — executable file (mode with the execute bit set, `#!/usr/bin/env python3`) that puts its own directory on `sys.path`, calls `cli.main()`, and exits with the returned value.

Dispatch is a skeleton in this story; later stories register commands and argument parsing.

# FEATURE: Options

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Parses and validates the command, its options, and the file argument, raising a usage error for any malformed invocation. |
| Depends On  | FEATURE-CliFoundation.md |
| Provides    | parse_args |

## Questions

- None.

## Purpose

`cli.options.parse_args(argv) -> Parsed` turns the argument list into a validated `Parsed` record or raises `cli.errors.UsageError`. `UsageError` is defined in `cli/errors.py` (see `FEATURE-ExitCodes.md`); this story creates the module with both exception classes if it does not exist yet. The dispatcher maps `UsageError` to exit code 2.

## Grammar

```text
quakes fetch --start <YYYY-MM-DD> --end <YYYY-MM-DD> [--min-mag <m>] --out <file>
quakes summary [--min-mag <m>] <file>
quakes top [--min-mag <m>] [--n <count>] <file>
quakes daily [--min-mag <m>] <file>
quakes regions [--min-mag <m>] <file>
quakes near --lat <deg> --lon <deg> --radius <km> [--min-mag <m>] <file>
```

- The command is the first argument. Options follow in any order; the file (for report commands) is last.
- Each command accepts only its listed options; any other option is a `UsageError`.
- `<m>`, `<deg>`, `<km>` match `-?[0-9]+(\.[0-9]+)?` and a value may begin with `-`. Anything else is malformed.
- `<count>` is a positive integer (digits only, greater than zero), default `10`.
- `--lat` is within -90 to 90, `--lon` within -180 to 180, `--radius` greater than zero. `near` requires all three.
- `fetch` requires `--start`, `--end`, `--out`; dates match `YYYY-MM-DD`. `fetch` takes no positional file. `--min-mag` defaults to `2.5` for `fetch`; for report commands it is `None` when omitted.
- A missing command, unknown command, missing option value, missing file, extra positional argument, or repeated option is a `UsageError` (decision Q-001).
- `parse_args` does not touch the file system.

# FEATURE: Exit Codes

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Maps usage and operational failures to exit codes 2 and 1 with empty standard output and one standard-error line. |
| Depends On  | FEATURE-Options.md |
| Provides    | UsageError, OperationalError, exit code mapping |

## Questions

- None.

## Purpose

`cli/errors.py` defines `UsageError` (exit 2) and `OperationalError` (exit 1), both subclasses of a common `QuakesError(Exception)` carrying a one-line message. `cli.main` parses arguments, looks up the handler in `cli.COMMANDS`, and runs it.

## Behavior

- Success, including a report with no matching events, returns `0` after writing the handler's returned text to standard output.
- `UsageError` returns `2`; `OperationalError` returns `1`.
- On either failure `main` writes nothing to standard output and exactly one diagnostic line (ending in a single newline, no embedded newline) to standard error.
- Handlers return their complete output text and write nothing themselves, so a failure leaves standard output empty.
- An unexpected exception is not mapped; only the two named errors are.

# FEATURE: Formatting

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Formats UTC times, magnitudes, depths, distances, and CSV output for every report. |
| Depends On  | ARCHITECTURE.md |
| Provides    | format_time, format_mag, format_mean, format_decimal, write_csv |

## Questions

- None.

## Purpose

`cli/formatting.py` holds the pure formatting functions every report uses.

## Interface

- `format_time(ms: int | float) -> str` — epoch milliseconds to UTC `YYYY-MM-DDTHH:MM:SSZ`, truncated (floored) to whole seconds. The date is the first 10 characters.
- `format_mag(x) -> str` — one decimal place (`5.0`, `7.1`).
- `format_mean(x) -> str` — two decimal places, rounded half up.
- `format_decimal(x) -> str` — one decimal place, rounded half up (used for `depth_km` and `distance_km`).
- `render_csv(rows) -> str` — rows (lists of strings) rendered with Python's `csv` module, `lineterminator="\n"`, so a field containing a comma is quoted.
- `write_csv(rows, stream=None)` — writes `render_csv(rows)` to `stream`; when `stream` is `None` it writes UTF-8 to standard output (the underlying binary buffer when present, otherwise `sys.stdout.write`).

Rounding uses `decimal.Decimal(repr(x))` quantized with `ROUND_HALF_UP` (decision Q-002); built-in `round()` is not used. Output is UTF-8 and non-ASCII place names are written unescaped.

## Programmatic Acceptance
