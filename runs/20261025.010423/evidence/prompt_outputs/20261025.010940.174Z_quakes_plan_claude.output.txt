# FEATURE: Daily

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | The `daily` report: event count and maximum magnitude per UTC date, followed by a TOTAL row. |
| Depends On  | FEATURE-MagFilter.md, FEATURE-Formatting.md, FEATURE-Options.md, FEATURE-ExitCodes.md |
| Provides    | quakes daily |
| Consumes    | read_feed, extract_events, filter_events, write_csv, format_time, format_mag, parse_args |

## Questions

- None.

## Purpose

`quakes daily [--min-mag <m>] <file>` reads a saved USGS GeoJSON file and reports how many events occurred on each UTC date and the strongest magnitude on that date.

## Trigger

Command line: `./quakes daily [--min-mag <m>] <file>`. The command accepts only `--min-mag`; any other option is a usage error handled by `parse_args`.

## Sequence

1. `read_feed(file)` validates and returns the features (`OperationalError`, exit 1, on failure).
2. `extract_events` drops null-magnitude features.
3. `filter_events(events, min_mag)` applies `--min-mag`.
4. `compute_daily(events)` groups events by date, where date is the first 10 characters of `format_time(event.time)`.
5. Rows are ordered by date ascending (byte order), followed by one `TOTAL` row.
6. `write_csv` writes the whole report to standard output in one step, after it is fully computed.

`compute_daily(events)` is a pure function returning `(rows, total_row)` with no I/O; formatting is performed by the `format_daily` step that uses `format_mag` and `write_csv`.

## Output

Header: `date,events,max_mag`.

- One row per date that has at least one event, ascending.
- `events` is the integer count; `max_mag` is the maximum magnitude with one decimal.
- Final row: `TOTAL,<events>,<max_mag>` where both values are over all kept events.
- With no events the output is the header followed by `TOTAL,0,` (empty max).
- Exit code 0, including the empty case.

## Reads

The saved GeoJSON file named on the command line. No other input.

## Writes

Standard output only. Nothing is written to any file.

import csv
import io
import json
import os
import tempfile
from datetime import datetime, timezone

from cli.testing import cli_runner


def ms(day, hour, minute=0, second=0, milli=0):
    moment = datetime(2025, 1, day, hour, minute, second, tzinfo=timezone.utc)
    return int(moment.timestamp()) * 1000 + milli


def feat(i, mag, t):
    return {
        "type": "Feature",
        "properties": {"mag": mag, "place": "10 km N of Town, Land", "time": t, "tsunami": 0},
        "geometry": {"type": "Point", "coordinates": [10.0, 20.0, 5.0]},
        "id": "e" + str(i),
    }


specs = [
    (5.0, ms(3, 1)),
    (6.1, ms(1, 2)),
    (5.4, ms(1, 23, 59, 59, 999)),
    (5.5, ms(3, 12)),
    (5.2, ms(7, 0)),
]
expected = {}
for mag, t in specs:
    label = datetime.fromtimestamp(t // 1000, timezone.utc).strftime("%Y-%m-%d")
    entry = expected.setdefault(label, [0, mag])
    entry[0] += 1
    entry[1] = max(entry[1], mag)

doc = {"type": "FeatureCollection", "features": [feat(i, m, t) for i, (m, t) in enumerate(specs)]}
with tempfile.TemporaryDirectory() as tmp:
    path = os.path.join(tmp, "q.geojson")
    with open(path, "w", encoding="utf-8") as fh:
        json.dump(doc, fh)
    code, out, err = cli_runner("daily", path)
print(out)
print(err)
assert code == 0
rows = list(csv.reader(io.StringIO(out)))
assert rows[0] == ["date", "events", "max_mag"]
body = rows[1:-1]
assert [r[0] for r in body] == sorted(expected)
for r in body:
    assert int(r[1]) == expected[r[0]][0]
    assert float(r[2]) == expected[r[0]][1]
total = rows[-1]
assert total[0] == "TOTAL"
assert int(total[1]) == len(specs)
assert float(total[2]) == max(m for m, _ in specs)

# FEATURE: Regions

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | The `regions` report: event count and maximum magnitude per region derived from the place text. |
| Depends On  | FEATURE-MagFilter.md, FEATURE-Formatting.md, FEATURE-Options.md, FEATURE-ExitCodes.md |
| Provides    | quakes regions |
| Consumes    | read_feed, extract_events, filter_events, write_csv, format_mag, parse_args |

## Questions

- None.

## Purpose

`quakes regions [--min-mag <m>] <file>` reports the most active regions in a saved USGS GeoJSON file.

## Trigger

Command line: `./quakes regions [--min-mag <m>] <file>`. Only `--min-mag` is accepted.

## Sequence

1. `read_feed`, `extract_events`, and `filter_events` produce the kept events.
2. `region_of(place)` is a pure function: the text after the last `", "` (comma, space) in `place`; the whole `place` when it has none; `"Unknown"` when `place` is `None`.
3. `compute_regions(events)` counts events and tracks the maximum magnitude per region.
4. Rows are ordered by events descending, then region ascending by byte value (plain code point order, so uppercase sorts before lowercase).
5. `write_csv` writes the complete report.

## Output

Header: `region,events,max_mag`. One row per region; `max_mag` has one decimal. With no events, the output is only the header, exit 0. A region containing a comma cannot occur (the last `", "` is split on), but quoting is always delegated to the `csv` module. Non-ASCII region names are written as UTF-8.

## Reads

The saved GeoJSON file named on the command line.

## Writes

Standard output only.

# FEATURE: Near

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | The `near` report: events within a haversine great-circle distance of a point, nearest first. |
| Depends On  | FEATURE-MagFilter.md, FEATURE-Formatting.md, FEATURE-Options.md, FEATURE-ExitCodes.md |
| Provides    | quakes near, haversine_km |
| Consumes    | read_feed, extract_events, filter_events, write_csv, format_time, format_mag, format_decimal, parse_args |

## Questions

- None.

## Purpose

`quakes near --lat <deg> --lon <deg> --radius <km> [--min-mag <m>] <file>` lists the events whose distance from a point is at most the radius.

## Trigger

Command line. `--lat`, `--lon`, and `--radius` are all required. `parse_args` enforces `--lat` in -90..90, `--lon` in -180..180, and `--radius` greater than zero; any violation or omission is a usage error (exit 2).

## Sequence

1. `read_feed`, `extract_events`, and `filter_events` produce the kept events.
2. `haversine_km(lat1, lon1, lat2, lon2)` is a pure function on a sphere of radius 6371.0 km, with angles in radians:
   `h = sin^2((lat2 - lat1) / 2) + cos(lat1) * cos(lat2) * sin^2((lon2 - lon1) / 2)` and `d = 2 * 6371.0 * asin(sqrt(h))`. Event coordinates are `[longitude, latitude, depth_km]`.
3. `compute_near(events, lat, lon, radius)` keeps events whose unrounded distance is `<= radius` and orders them by unrounded distance ascending, then by event time ascending.
4. `write_csv` writes the report, with `distance_km` rounded half up to one decimal.

## Output

Header: `distance_km,time,mag,place,id`. One row per matching event: distance with one decimal, UTC time, magnitude with one decimal, place, id. An event at exactly the radius is included. No matches yields only the header with exit 0. Places containing commas are quoted by the `csv` module; non-ASCII places are UTF-8.

## Reads

The saved GeoJSON file named on the command line.

## Writes

Standard output only.

## Programmatic Acceptance

=== AC near-haversine-distance-and-radius ===
Intent: Reported distances match an independent haversine on a 6371.0 km sphere, and only events within the radius are listed, nearest first.
Suite: scoped
Requires: executable=python3; scope=test

import csv
import io
import json
import math
import os
import tempfile

from cli.testing import cli_runner


def hav(lat1, lon1, lat2, lon2):
    p1, p2 = math.radians(lat1), math.radians(lat2)
    dphi = p2 - p1
    dlam = math.radians(lon2 - lon1)
    h = math.sin(dphi / 2) ** 2 + math.cos(p1) * math.cos(p2) * math.sin(dlam / 2) ** 2
    return 2 * 6371.0 * math.asin(math.sqrt(h))


origin = (27.72, 85.32)
points = [
    ("far", 35.68, 139.69),
    ("mid", 28.60, 87.37),
    ("near1", 28.80, 87.13),
    ("near2", 28.50, 87.35),
]
features = []
for i, (name, lat, lon) in enumerate(points):
    features.append({
        "type": "Feature",
        "properties": {"mag": 5.0 + i / 10, "place": "Place " + name, "time": 1736200000000 + i * 1000, "tsunami": 0},
        "geometry": {"type": "Point", "coordinates": [lon, lat, 10.0]},
        "id": name,
    })
doc = {"type": "FeatureCollection", "features": features}
dist = {name: hav(origin[0], origin[1], lat, lon) for name, lat, lon in points}
radius = round(sorted(dist.values())[2] + 1.0, 1)
inside = sorted([n for n in dist if dist[n] <= radius], key=lambda n: dist[n])
assert 0 < len(inside) < len(points)
with tempfile.TemporaryDirectory() as tmp:
    path = os.path.join(tmp, "q.geojson")
    with open(path, "w", encoding="utf-8") as fh:
        json.dump(doc, fh)
    code, out, err = cli_runner(
        "near", "--lat", str(origin[0]), "--lon", str(origin[1]), "--radius", str(radius), path
    )
print(out)
print(err)
assert code == 0
rows = list(csv.reader(io.StringIO(out)))
assert rows[0] == ["distance_km", "time", "mag", "place", "id"]
assert [r[4] for r in rows[1:]] == inside
for r in rows[1:]:
    assert abs(float(r[0]) - dist[r[4]]) <= 0.051
=== END AC near-haversine-distance-and-radius ===

# FEATURE: Fetch

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | The `fetch` command: download a USGS date range as GeoJSON and save the response unchanged to a file. |
| Depends On  | FEATURE-Options.md, FEATURE-ExitCodes.md, FEATURE-FeedValidation.md |
| Provides    | quakes fetch, build_url, http_get |
| Consumes    | parse_args, read_feed |

## Questions

- None.

## Purpose

`quakes fetch --start <YYYY-MM-DD> --end <YYYY-MM-DD> [--min-mag <m>] --out <file>` saves a period of the USGS event feed so the report commands can read it.

## Trigger

Command line. `--start`, `--end`, and `--out` are required; `--min-mag` defaults to `2.5`. A missing required option, an unlisted option, or any positional argument is a usage error (exit 2) and no HTTP call is made.

## Module layout

Code lives in `cli/fetch.py`:

- `build_url(start, end, min_mag) -> str` returns `https://earthquake.usgs.gov/fdsnws/event/1/query` with query parameters `format=geojson`, `starttime=<start>`, `endtime=<end>`, `minmagnitude=<min_mag>`, `orderby=time-asc`. `min_mag` is the text given on the command line (or `2.5`).
- `http_get(url) -> tuple[int, bytes]` is the single replaceable network function. It calls `urllib.request.urlopen` through attribute access on the `urllib.request` module (so a test can patch `urllib.request.urlopen`), returns the HTTP status and body bytes, and is the only function in the product that opens a connection.
- The command handler calls `http_get` through the module global (`cli.fetch.http_get`) so tests can replace it.

## Sequence

1. Build the URL and call `http_get(url)`.
2. Validate: status 200, body parses as JSON, and is an object with `"type": "FeatureCollection"` and a list `features` (reusing the `read_feed` validation rules on the body).
3. Only after validation, write the body bytes unchanged (binary write) to `--out`.
4. Write `fetched,<count>` to standard output, where `<count>` is the number of features.

Failure handling is specified in FEATURE-FetchFailure.md.

## Output

Standard output is exactly one CSV line `fetched,<count>`; exit 0. The saved file is byte-for-byte the response body.

## Reads

The USGS FDSN event web service over HTTPS.

## Writes

The file named by `--out`, and standard output.

# FEATURE: Fetch Failure

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Failure behavior of `fetch`: network, HTTP, and body errors exit 1 and never write or alter a file. |
| Depends On  | FEATURE-Fetch.md, FEATURE-ExitCodes.md |
| Provides    | fetch failure handling |
| Consumes    | http_get |

## Questions

- None.

## Purpose

When the download cannot produce a valid GeoJSON FeatureCollection, `fetch` reports an operational failure and leaves the filesystem exactly as it found it.

## Trigger

Any of the following during `quakes fetch` (after arguments parse successfully):

- a network error (any `urllib.error.URLError`, `OSError`, or timeout from the HTTP layer);
- an HTTP status other than 200;
- a 200 body that is not JSON, or is JSON but not an object with `"type": "FeatureCollection"` and a list `features`.

## Behavior

- `http_get` returns `(status, body)` for every HTTP response, including non-200 statuses (an `HTTPError` is converted to its code and body), and raises `OperationalError` for `URLError`, `OSError`, and timeouts.
- The `fetch` handler also converts any `OSError` raised by a replaced `http_get` into `OperationalError`.
- A non-200 status or an invalid body raises `OperationalError`.
- All checks complete before `--out` is opened, so no file is created and a pre-existing file at `--out` keeps its exact bytes.
- The command exits 1, writes nothing to standard output, and writes one diagnostic line to standard error.

## Reads

The HTTP response only.

## Writes

Standard error only; never the output file on failure.

## Programmatic Acceptance
