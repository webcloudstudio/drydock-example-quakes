# FEATURE: Feed Validation

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Read a saved GeoJSON file and confirm it is a USGS FeatureCollection. |
| Depends On  | ARCHITECTURE.md, FEATURE-ExitCodes.md |
| Provides    | read_feed |
| Consumes    | OperationalError |

## Questions

- None.

## Purpose

Every report command starts by reading a saved feed file. `read_feed` returns the raw `features` list
and rejects anything that is not a GeoJSON FeatureCollection as an operational failure (exit 1).

## Interface

- Module: `cli.feed`. Function: `read_feed(path) -> list`.
- `path` is a `str` or `pathlib.Path`. The file is read as UTF-8 and parsed with `json`.
- Returns the value of the `features` array unchanged (a `list` of feature objects).
- Raises `OperationalError` when:
  - the file cannot be read (missing, directory, permissions, undecodable bytes),
  - the content is not valid JSON,
  - the JSON value is not an object,
  - `"type"` is not the string `FeatureCollection`,
  - `features` is missing or not an array.
- An empty `features` array is valid and returns `[]`.
- The function writes nothing to standard output. The diagnostic line is produced by `main`.

# FEATURE: Event Extraction

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Turn GeoJSON features into event records and drop events with a null magnitude. |
| Depends On  | FEATURE-FeedValidation.md |
| Provides    | extract_events, Event |
| Consumes    | read_feed |

## Questions

- None.

## Purpose

Reports operate on `Event` records, not raw features. Extraction reads only the fields the reports
need and excludes every feature whose magnitude is `null`.

## Interface

- Module: `cli.feed`. Function: `extract_events(features) -> list[Event]`, preserving feed order.
- `Event` is an immutable dataclass with fields:
  - `id` (str), `mag` (float), `place` (str or `None`),
  - `time_ms` (int, milliseconds since the Unix epoch), `tsunami` (int),
  - `lon` (float), `lat` (float), `depth_km` (float).
- Source fields: `id`, `properties.mag`, `properties.place`, `properties.time`,
  `properties.tsunami`, and `geometry.coordinates` as `[longitude, latitude, depth_km]`.
  Every other field is ignored.
- A feature whose `properties.mag` is `null` is dropped. A magnitude of `0` is kept.
- A `null` place stays `None`; the regions report maps it to `Unknown`.
- A missing `tsunami` is read as `0`.

## Programmatic Acceptance

# FEATURE: Magnitude Filter

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Keep only events whose magnitude is at least the --min-mag value. |
| Depends On  | FEATURE-EventExtraction.md |

## Questions

- None.

## Purpose

`--min-mag <m>` applies to every report. `filter_events` is the single shared implementation, so

## Interface

- Module: `cli.feed`. Function: `filter_events(events, min_mag) -> list[Event]`.

# FEATURE: Summary Report

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | The summary command reports event count, time span, magnitude range, mean, and tsunami count. |
| Depends On  | FEATURE-MagFilter.md, FEATURE-Formatting.md, FEATURE-Options.md, FEATURE-ExitCodes.md |
| Provides    | quakes summary |
| Consumes    | read_feed, extract_events, filter_events, write_csv, parse_args |

## Questions

- None.

## Purpose

`quakes summary [--min-mag <m>] <file>` reads a saved feed, applies the filter, and writes a
one-row CSV report to standard output.

## Behavior

- Header: `events,first,last,min_mag,max_mag,mean_mag,tsunami`.
- One data row computed over the filtered events:
  - `events`: the count.
  - `first` / `last`: the earliest and latest event times, formatted `YYYY-MM-DDTHH:MM:SSZ`.
  - `min_mag` / `max_mag`: one decimal place.
  - `mean_mag`: arithmetic mean, two decimals, rounded half up.
  - `tsunami`: the number of events whose `tsunami` equals `1`.
- With no events the row is `0,,,,,,0`.
- Only `--min-mag` is accepted; any other option is a usage error (exit 2).
- Success, including the empty report, exits `0`. An unreadable or invalid file exits `1` with
  nothing on standard output.

## Programmatic Acceptance

# FEATURE: Top Report

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | The top command lists the largest events by magnitude. |
| Depends On  | FEATURE-MagFilter.md, FEATURE-Formatting.md, FEATURE-Options.md, FEATURE-ExitCodes.md |
| Provides    | quakes top |
| Consumes    | read_feed, extract_events, filter_events, write_csv, parse_args |

## Questions

- None.

## Purpose

`quakes top [--min-mag <m>] [--n <count>] <file>` writes the `--n` largest events as CSV.

## Behavior

- Header: `time,mag,depth_km,place,id`.
- Events are filtered by `--min-mag` first, then sorted by magnitude descending, then time ascending
  (ties beyond that keep feed order), then the first `--n` are written.
- `--n` is a positive integer and defaults to `10`. `--n 0` or a non-integer is a usage error (exit 2).
- `time` is `YYYY-MM-DDTHH:MM:SSZ`; `mag` and `depth_km` have one decimal place.
- A place containing a comma is quoted by the `csv` module.
- Only `--min-mag` and `--n` are accepted. No matching events yields the header alone with exit `0`.

## Programmatic Acceptance
