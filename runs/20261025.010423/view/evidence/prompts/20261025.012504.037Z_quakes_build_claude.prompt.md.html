import contextlib
import io
from cli import main

def cli_runner(*args: str) -> tuple[int, str, str]:
    """Return (exit_code, stdout, stderr) without spawning a process."""
    out, err = io.StringIO(), io.StringIO()
    with contextlib.redirect_stdout(out), contextlib.redirect_stderr(err):

    return code, out.getvalue(), err.getvalue()

## 1. Directory Layout

**Rule**: Command code lives in `cli/`. The root holds only packaging and infrastructure files.

```
project/
  pyproject.toml            # [project.scripts] declares the console script
  cli/
    __init__.py             # main() — the single entry point
    commands.py             # one function per command; no argument parsing
    parser.py               # argparse construction; no behavior
  bin/
    run.sh                  # bash launcher
    run.ps1                 # PowerShell launcher
  tests/
```

**Why**: Parsing, behavior, and launching are three contracts. Collapsing them produces a command
that cannot be tested without a shell.

---

## 2. Entry Point and Exit Codes

**Rule**: `main(argv=None) -> int` parses, dispatches, and returns an exit code. It never calls
`sys.exit` and never raises for an expected failure. The console script is the only caller that
translates the return value into a process exit.

```python
# cli/__init__.py
import sys
from cli.parser import build_parser
from cli import commands

def main(argv: list[str] | None = None) -> int:
    args = build_parser().parse_args(argv)
    try:
        return commands.dispatch(args)
    except OperationalError as exc:
        print(f"error: {exc}", file=sys.stderr)
        return 1
```

```toml
# pyproject.toml
[project.scripts]
mytool = "cli:main"
```

**Exit codes**: `0` success, `1` operational failure, `2` usage error. `argparse` already returns
`2` for a usage error; do not override it.

**Why**: A `main` that returns rather than exits is callable from a test in-process. A `main` that
calls `sys.exit` forces every criterion to spawn a subprocess and measure the shell.

---

## 3. Parsing Is Separate From Behavior

**Rule**: `parser.py` builds the `argparse` tree and returns it. `commands.py` holds one function
per command taking plain arguments, not a `Namespace`. Neither imports the other.

```python
# cli/parser.py
import argparse

def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(prog="mytool")
    sub = parser.add_subparsers(dest="command", required=True)
    status = sub.add_parser("status", help="Report current state")
    status.add_argument("--json", action="store_true")
    return parser
```

```python
# cli/commands.py
def status(*, as_json: bool) -> int:
    ...

def dispatch(args) -> int:
    if args.command == "status":
        return status(as_json=args.json)
    return 2
```

**Why**: Behavior tested through a `Namespace` is behavior tested through the parser. Separating
them lets a criterion call `status(as_json=True)` directly.

---

## 4. Cross-Platform Launchers

**Rule**: Ship both launchers. They locate the environment and invoke the package entry point;
they contain no business logic. A launcher that makes a decision is a second implementation of the
command.

```bash
#!/usr/bin/env bash
# bin/run.sh — locate the environment and hand off. No business logic.
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
if [ -d "$ROOT/.venv" ]; then
    source "$ROOT/.venv/bin/activate"
fi
exec python -m cli "$@"
```

```powershell
# bin/run.ps1 — locate the environment and hand off. No business logic.
$ErrorActionPreference = "Stop"
$Root = Split-Path -Parent $PSScriptRoot
$Activate = Join-Path $Root ".venv\Scripts\Activate.ps1"
if (Test-Path $Activate) { & $Activate }
python -m cli @args
exit $LASTEXITCODE
```

```python
# cli/__main__.py — makes `python -m cli` work identically on both platforms
import sys
from cli import main

sys.exit(main())
```

**Why**: `python -m cli` is the one invocation both launchers share, so the two scripts cannot
drift in behavior — only in how they find the interpreter. `exit $LASTEXITCODE` is required in
PowerShell; without it the exit code is discarded and a failing command reports success.

---

## 5. Output and Streams

**Rule**: Results go to stdout, diagnostics to stderr. A `--json` mode prints one JSON document to
stdout and nothing else. Never interleave progress text into a machine-readable stream.

**Why**: A caller piping stdout to `jq` receives the progress lines too, and the command becomes
unusable in a pipeline.

---

## 6. Testing Without a Process

**Rule**: Test through `main(["status", "--json"])` or the `cli_runner` fixture. Reserve
`subprocess.run` for one packaging test asserting the installed console script exists and runs.

```python
def test_status_reports_json(cli_runner):
    code, out, err = cli_runner("status", "--json")
    assert code == 0
    assert json.loads(out)["state"] == "ready"
    assert err == ""
```

**Why**: In-process tests are fast, debuggable, and measure the code. Subprocess tests measure the
installed environment, which is a different and much smaller question.

## Purpose

`quakes summary [--min-mag <m>] <file>` reads a saved feed, applies the filter, and writes a
one-row CSV report to standard output.

## Behavior

- Header: `events,first,last,min_mag,max_mag,mean_mag,tsunami`.
- One data row computed over the filtered events:
  - `events`: the count.
  - `first` / `last`: the earliest and latest event times, formatted `YYYY-MM-DDTHH:MM:SSZ`.
  - `min_mag` / `max_mag`: one decimal place.
  - `mean_mag`: arithmetic mean, two decimals, rounded half up.
  - `tsunami`: the number of events whose `tsunami` equals `1`.
- With no events the row is `0,,,,,,0`.
- Only `--min-mag` is accepted; any other option is a usage error (exit 2).
- Success, including the empty report, exits `0`. An unreadable or invalid file exits `1` with
  nothing on standard output.

## Purpose

## Sequence

- `events` is the integer count; `max_mag` is the maximum magnitude with one decimal.

- With no events the output is the header followed by `TOTAL,0,` (empty max).
- Exit code 0, including the empty case.

## Reads

The saved GeoJSON file named on the command line. No other input.

## Writes

Standard output only. Nothing is written to any file.

# FEATURE: Fetch Failure

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Failure behavior of `fetch`: network, HTTP, and body errors exit 1 and never write or alter a file. |
| Depends On  | FEATURE-Fetch.md, FEATURE-ExitCodes.md |
| Provides    | fetch failure handling |
| Consumes    | http_get |

## Purpose

When the download cannot produce a valid GeoJSON FeatureCollection, `fetch` reports an operational failure and leaves the filesystem exactly as it found it.

## Trigger

Any of the following during `quakes fetch` (after arguments parse successfully):

- a network error (any `urllib.error.URLError`, `OSError`, or timeout from the HTTP layer);
- an HTTP status other than 200;
- a 200 body that is not JSON, or is JSON but not an object with `"type": "FeatureCollection"` and a list `features`.

## Behavior

- `http_get` returns `(status, body)` for every HTTP response, including non-200 statuses (an `HTTPError` is converted to its code and body), and raises `OperationalError` for `URLError`, `OSError`, and timeouts.
- The `fetch` handler also converts any `OSError` raised by a replaced `http_get` into `OperationalError`.
- A non-200 status or an invalid body raises `OperationalError`.
- All checks complete before `--out` is opened, so no file is created and a pre-existing file at `--out` keeps its exact bytes.
- The command exits 1, writes nothing to standard output, and writes one diagnostic line to standard error.

## Reads

The HTTP response only.

## Writes

Standard error only; never the output file on failure.

# FEATURE: Near

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | The `near` report: events within a haversine great-circle distance of a point, nearest first. |
| Depends On  | FEATURE-MagFilter.md, FEATURE-Formatting.md, FEATURE-Options.md, FEATURE-ExitCodes.md |
| Provides    | quakes near, haversine_km |
| Consumes    | read_feed, extract_events, filter_events, write_csv, format_time, format_mag, format_decimal, parse_args |

## Purpose

`quakes near --lat <deg> --lon <deg> --radius <km> [--min-mag <m>] <file>` lists the events whose distance from a point is at most the radius.

## Trigger

Command line. `--lat`, `--lon`, and `--radius` are all required. `parse_args` enforces `--lat` in -90..90, `--lon` in -180..180, and `--radius` greater than zero; any violation or omission is a usage error (exit 2).

## Sequence

1. `read_feed`, `extract_events`, and `filter_events` produce the kept events.
2. `haversine_km(lat1, lon1, lat2, lon2)` is a pure function on a sphere of radius 6371.0 km, with angles in radians:
   `h = sin^2((lat2 - lat1) / 2) + cos(lat1) * cos(lat2) * sin^2((lon2 - lon1) / 2)` and `d = 2 * 6371.0 * asin(sqrt(h))`. Event coordinates are `[longitude, latitude, depth_km]`.
3. `compute_near(events, lat, lon, radius)` keeps events whose unrounded distance is `<= radius` and orders them by unrounded distance ascending, then by event time ascending.
4. `write_csv` writes the report, with `distance_km` rounded half up to one decimal.

## Output

Header: `distance_km,time,mag,place,id`. One row per matching event: distance with one decimal, UTC time, magnitude with one decimal, place, id. An event at exactly the radius is included. No matches yields only the header with exit 0. Places containing commas are quoted by the `csv` module; non-ASCII places are UTF-8.

## Reads

The saved GeoJSON file named on the command line.

## Writes

Standard output only.
